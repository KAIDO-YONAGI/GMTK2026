# 场景加载与面板系统 —— 使用说明

> 本文档说明项目中**已配置的**场景加载系统和面板系统的使用方法。
> 以下所有陈述均基于实际代码和当前编辑器状态，无任何杜撰。

---

## 第一部分 —— 场景加载系统

### 1.1 架构（当前实际存在的内容）

**Build Settings** 中注册了 4 个场景，顺序如下：

| Build Index | 场景 | 角色 |
|---|---|---|
| 0 | `Assets/Scenes/InitialScene.unity` | 入口场景（Unity 启动时加载） |
| 1 | `Assets/Scenes/PersistentScene.unity` | 常驻场景；承载所有跨场景单例 |
| 2 | `Assets/Scenes/StartingMenu.unity` | 内容场景 —— 主菜单 |
| 3 | `Assets/Scenes/Level01.unity` | 内容场景 —— 一个关卡 |

**PersistentScene 层级结构**（已在编辑器中核实）：

```
Managers                          (空的容器 GameObject)
├── SceneChanger    [SceneChanger]
├── TimeManager     [TimeManager]
└── UIManager       [UIManager]
FadeCanvas          [Canvas + CanvasGroup + ...]
ESCPanel            [Canvas + CanvasGroup + ESCMenuManager]   ← 见第二部分
└── Background / Title / ResumeButton / MenuButton
EventSystem         [EventSystem + StandaloneInputModule]
```

### 1.2 启动链（在打开 `InitialScene` 后按 Play 会发生什么）

启动链基于 `InitialLoad.cs` 和 `SceneChanger.cs` 的实际代码：

1. Unity 加载 `InitialScene`（Build Index 0）。
2. `InitialLoad.Awake()` 执行 `SceneManager.LoadSceneAsync(persistentSceneName, LoadSceneMode.Additive)`。
   - `persistentSceneName` 在 `InitialScene` 内的 `Bootstrapper` GameObject 上设置。当前值：**`PersistentScene`**。
3. `PersistentScene` 以 Additive 方式加载。其单例执行 `Awake()`：
   - `SceneChanger.Awake()` 设置 `instance = this`，然后调用 `LoadScene(initScene)`。
   - `initScene` 是 Inspector 中指定的 `GameSceneSO` 资产。当前值：**`StartingMenuSO`**。
4. `LoadScene()` 执行 `SceneManager.LoadSceneAsync(sceneToLoad.sceneName, LoadSceneMode.Additive)`，以 Additive 方式加载 `StartingMenu`。
5. 异步操作完成后，`OnLoadCompleted()` 执行：
   - 设置 `currentScene = sceneToLoad`
   - 设置 `loadedScene = SceneManager.GetSceneByName(sceneToLoad.sceneName)`
   - 触发 `sceneLoadedEvent`（一个 `VoidEventSO`）
   - 调用 `TimeManager.instance.ForceResumeGame()`

启动结束状态：`InitialScene + PersistentScene + StartingMenu` 全部已加载。`PersistentScene` **永远不会被 SceneChanger 卸载**（它只卸载 `currentScene`，而 `currentScene` 只会被设置为内容场景如 `StartingMenu`/`Level01`）。

### 1.3 运行时如何切换场景

唯一的入口是 **`SceneLoadEventSO.RaiseLoadRequestEvent(GameSceneSO, Vector3, bool)`**。代码库中除了 `SceneChanger` 和 `InitialLoad` 之外，没有任何地方直接调用 `SceneManager.LoadScene`。

代码库中存在三个调用方：

| 调用方 | 触发方式 | 代码 |
|---|---|---|
| `ButtonSceneToggler.HandleSceneToggle()` | UI Button 的 `onClick`（在 Inspector 中绑定） | 调用 `RaiseLoadRequestEvent(sceneToLoad, newPosition, isToFade)` —— 但若 `sceneToLoad.sceneType == Retry`，则改为触发 `retryEventSO` |
| `SceneToggler.OnTriggerEnter2D(Collider2D)` | 某个 `Collider2D` 进入触发器 | 调用 `RaiseLoadRequestEvent(sceneToLoad, newPosition, isToFade)` |
| `RetryManager.OnReTry()` | 订阅了 `VoidEventSO retryEventSO` | 调用 `RaiseLoadRequestEvent(currentScene, Vector3.zero, true)` |

当 `RaiseLoadRequestEvent` 触发时，`SceneChanger.OnLoadRequestEvent` 同步执行（UIManager 的 `DefaultExecutionOrder(-100)` 保证 UIManager 先处理该事件）：

1. `TimeManager.instance.PauseGame()` → `Time.timeScale = 0`
2. 设置 `sceneToLoad`、`newPosition`、`isToFade`
3. 若 `isToFade && !isInitialScene`：执行 `PlayLoadingAnimation("FadeIn")`（设置 `fadeCanva.alpha = 1`，播放 `transitionImagesDuringFade` 中的 Animator）
4. 启动协程 `UnloadCurrentScene`：
   - `yield return new WaitForSecondsRealtime(fadeDuration)` —— 使用真实时间（不受 `timeScale = 0` 影响）
   - `yield return SceneManager.UnloadSceneAsync(currentScene.sceneName)`
   - `LoadScene(sceneToLoad)` —— Additive 加载
   - `SetPlayerPostion(newPosition)` —— 若 `player == null` 则直接返回（已加空检查，当前状态：`player = NULL`）

> ⚠️ `SceneChanger` 的 `player` 字段当前未赋值。`SetPlayerPostion` 有空检查，会静默返回。如果你的游戏需要在场景切换后重新定位玩家，请在 `PersistentScene` 中把玩家 GameObject 拖到 `SceneChanger` 的 `player` 字段上。

### 1.4 如何添加新的内容场景

按以下步骤操作（每一步都是代码要求的）：

1. **创建场景文件**（如 `Assets/Scenes/Level02.unity`）。
2. **加入 Build Settings** —— `File → Build Settings → Add Open Scenes`，或通过 `manage_build action=scenes`。`SceneManager.LoadSceneAsync(sceneName)` 只能解析在 Build Settings 中的场景名。
3. **创建 `GameSceneSO.asset`** —— Project 窗口 → `Create → GameSceneSO → SceneSO`。设置：
   - `sceneAsset`：把新的 `.unity` 文件拖到这里（仅编辑器；保存时通过 `OnValidate` 自动同步 `sceneName`）
   - `sceneName`：由 `sceneAsset` 自动填充（请勿手动输入）
   - `sceneType`：关卡用 `Location`，菜单用 `Menu`，重试用 `Retry`
   - `initialPosition`：玩家出生点（当调用方传入 `Vector3.zero` 时使用）
4. **触发切换** —— 使用 §1.3 中三个调用方之一：把新的 `GameSceneSO` 指给 `sceneToLoad`，把共享的 `SceneLoadEvent.asset` 指给 `loadEventSO`。

### 1.5 字段说明 —— `GameSceneSO`

来自 `GameSceneSO.cs`：

| 字段 | 类型 | 由谁设置 | 运行时是否使用 |
|---|---|---|---|
| `ID` | `string` | `OnValidate` 中自动生成的 GUID（仅编辑器） | 当前运行时未使用 |
| `sceneAsset` | `UnityEditor.SceneAsset`（仅编辑器） | Inspector 拖入 | 通过 `#if UNITY_EDITOR` 在打包时剥离 |
| `sceneName` | `string` | `OnValidate` 中由 `sceneAsset` 自动同步 | **`SceneChanger` 用它加载/卸载** |
| `sceneType` | `MyEnums.SceneType`（`Location`/`Menu`/`Retry`） | Inspector | `SceneChanger.LoadScene` 用它切换 `objectsToUnableWhileGameReset`；`ButtonSceneToggler` 用 `Retry` 分支 |
| `initialPosition` | `Vector3` | Inspector | 调用方传入 `Vector3.zero` 时的备用出生点 |

> ⚠️ **`OnValidate` 仅在编辑器中运行。** 打包后的 Player 无法生成 `ID` 或同步 `sceneName`。打包前务必在编辑器中保存 SO。

### 1.6 当前已创建的资产（已在编辑器中核实）

位于 `Assets/Scenes/SOInstances/`：

| 资产 | 类型 | 用途 |
|---|---|---|
| `InitialSceneSO.asset` | `GameSceneSO` | 描述 `InitialScene` |
| `PersistentSceneSO.asset` | `GameSceneSO` | 描述 `PersistentScene` |
| `StartingMenuSO.asset` | `GameSceneSO` | 描述 `StartingMenu`。被用作 `SceneChanger.initScene`。 |
| `Level01SO.asset` | `GameSceneSO` | 描述 `Level01`。被 `StartingMenu` 中的 `StartButton` 使用。 |
| `SceneLoadEvent.asset` | `SceneLoadEventSO` | 所有调用方和 `SceneChanger` 共同订阅的事件总线 |
| `SceneLoadedEvent.asset` | `VoidEventSO` | 由 `SceneChanger.OnLoadCompleted` 触发。当前无订阅者。 |
| `ToggleESCEvent.asset` | `ToggleCanvasEventSO` | 见第二部分 |

### 1.7 已知限制（与当前代码一致）

- **`objectsToUnableWhileGameReset`**（`SceneChanger` 上）当前是空数组。`SetObjects(true/false)` 会遍历它并根据 `sceneType` 切换 `GameObject.SetActive`。如果你有需要"在 Menu 时隐藏、在 Location 时显示"的 GameObject，请在此指定。
- **`transitionImagesDuringFade`** 当前是空数组。`PlayLoadingAnimation` 会遍历它；为空时只有 `fadeCanva.alpha = 1` 会执行。
- **`sceneLoadedEvent`** 当前无订阅者。它会被触发但什么也不会发生。如果需要加载后的逻辑，请订阅它。

## 第二部分 —— 面板系统（UIManager + ESC 面板）

### 2.1 架构（当前实际存在的内容）

面板系统是**事件驱动**的，不是直接调用。`UIManager` **不持有任何面板 GameObject 的引用**。它分发 `ToggleCanvasEventSO` 事件；面板订阅自己的事件 SO 并作出反应。

```
UIManager（位于 PersistentScene）
├── loadEventSO         → SceneLoadEventSO   （订阅以在场景加载时清空面板状态）
├── toggleCanvasEvents  → List<ToggleCanvasEventSO>   （当前：[ToggleESCEvent]）
└── inputBindings       → List<CanvasInputBinding>    （当前：[ESC → "Cancel"]）

ESCPanel（PersistentScene 中独立的 GameObject）
├── CanvasGroup（初始 alpha=0, interactable=false, blocksRaycasts=false）
├── ESCMenuManager
│   ├── ESCGroup          → 自己的 CanvasGroup
│   └── toggleESCEvent    → ToggleESCEvent（在 OnEnable 中订阅）
└── ResumeButton / MenuButton（UI Button）
```

`CanvasToToggle` 枚举（来自 `MyEnums.cs`）：

```
ESC, GameOver, Dialog, Default
```

### 2.2 ESC 面板如何打开（已由代码 + Play 测试核实）

按下 ESC 键：

1. `UIManager.Update()` 对每个 `inputBindings` 项读取 `Input.GetButtonDown(binding.buttonName)`。
   - 当前绑定：`canvas=ESC`，`buttonName="Cancel"`（Unity 默认的 ESC 轴名）。
2. 设置 `inputState[ESC] = true`，然后执行 `HandleESCInput()`：
   - 若无画布打开：`RaiseCanvasEvent(ESC, true)` —— 打开面板
   - 若有画布打开：`CloseLastCanvas()` —— 关闭最上层那个
3. `RaiseCanvasEvent(ESC, true)` 在 `toggleCanvasEvents` 中找到 `canvasToToggle == ESC` 的那个 `ToggleCanvasEventSO`，调用 `eventSO.RaiseToggleCanvasEvent(true)`。
4. `ESCMenuManager.OnESC(true)`（在 `OnEnable` 中订阅了 `ToggleESCEvent.toggleCanvasEvent`）执行：
   - `TimeManager.instance.PauseGame()` → `Time.timeScale = 0`
   - `ESCGroup.alpha = 1`，`interactable = true`，`blocksRaycasts = true`
   - `UIManager.instance.ReportCanvasState(ESC, true)` —— UIManager 记录面板为打开，并更新焦点

已核实的结束状态（Play 模式）：`ESCPanel.alpha = 1`，`Time.timeScale = 0`。

### 2.3 ESC 面板如何关闭

有两种方式：

**A. 再次按 ESC** —— `HandleESCInput()` 发现有画布打开，调用 `CloseLastCanvas()`，进而调用 `RaiseCanvasEvent(ESC, false)`。`ESCMenuManager.OnESC(false)` 执行 `ResumeGame()` 并隐藏面板。

**B. 点击 Resume** —— `ResumeButton.onClick` 绑定到 `ESCMenuManager.OnResumeButton()`：

```csharp
public void OnResumeButton()
{
    if (UIManager.instance != null)
        UIManager.instance.RequestCanvasClose(MyEnums.CanvasToToggle.ESC);
}
```

`RequestCanvasClose(ESC)` 调用 `RaiseCanvasEvent(ESC, false)` + `RefreshFocusAfterClose(ESC)`。结果与再次按 ESC 完全相同。

已核实的结束状态（Play 模式）：`ESCPanel.alpha = 0`，`Time.timeScale = 1`。

**C. 点击 "Return to Menu"** —— `MenuButton.onClick` 绑定到 `ESCMenuManager.OnReturnToMenuButton()`：

```csharp
public void OnReturnToMenuButton()
{
    if (UIManager.instance != null)
        UIManager.instance.RequestCanvasClose(MyEnums.CanvasToToggle.ESC);
    var sc = SceneChanger.instance;
    if (sc != null && sc.loadEventSO != null && sc.initScene != null)
        sc.loadEventSO.RaiseLoadRequestEvent(sc.initScene, Vector3.zero, true);
}
```

关闭 ESC 面板**并**触发 `SceneChanger` 加载 `initScene`（当前是 `StartingMenuSO`）。注意：这里通过 `sc.initScene` 硬编码了"回到初始场景"。如果你想回到别的菜单，不要直接使用此方法。

### 2.4 如何添加新面板（例如 `GameOver`）

模式由 `UIManager` 的设计决定。步骤（每一步都是必须的）：

1. **在 `MyEnums.CanvasToToggle` 中添加枚举值**（如 `GameOver`）。务必放在 `Default` **之前** —— 代码注释明确说明 `Default` 必须保持最后，因为 ESC 逻辑依赖它。
2. **创建 `ToggleCanvasEventSO.asset`** —— `Create → Events → ToggleCanvasEventSO`。在 Inspector 中把 `canvasToToggle` 设为新枚举值（如 `GameOver`）。
3. **把该 SO 追加到 `UIManager.toggleCanvasEvents`**（Inspector）。否则 `RaiseCanvasEvent(GameOver, ...)` 找不到匹配的 SO，静默失败。
4. **（可选）在 `UIManager.inputBindings` 中添加输入绑定** —— 仅当面板需要用按键打开时。设置 `canvas = GameOver`，`buttonName = "<Input 轴名>"`。若面板仅由代码通过 `RequestCanvasToggle` 打开，则跳过此步。
5. **在 `PersistentScene` 中构建面板 GameObject**（Canvas + CanvasGroup，初始 `alpha=0`）。
6. **为面板写一个 Manager MonoBehaviour**，遵循 `ESCMenuManager` 的模式：
   - 持有自己的 `CanvasGroup` 和 `ToggleCanvasEventSO` 引用
   - 在 `OnEnable` 中订阅 `toggleCanvasEvent += OnXxx`，在 `OnDisable` 中取消订阅
   - 在处理器中设置 `CanvasGroup` 状态，并调用 `UIManager.instance.ReportCanvasState(canvasToToggle, state)`，让 UIManager 跟踪开关顺序
7. **从代码中打开面板**：`UIManager.instance.RequestCanvasToggle(MyEnums.CanvasToToggle.GameOver);`
   **从代码中关闭**：`UIManager.instance.RequestCanvasClose(MyEnums.CanvasToToggle.GameOver);`

> ℹ️ `ICanvasManager` 是一个带默认方法的接口，用于标准化 `SetCanvaState` / `RefreshCanvaOrder`。它是可选的 —— `ESCMenuManager` **没有**实现它。如果你想要免费的焦点/sortingOrder 逻辑，可以实现它。

### 2.5 UIManager 公开 API（来自 `UIManager.cs`）

以下是面向外部调用方的方法：

| 方法 | 用途 |
|---|---|
| `RequestCanvasToggle(CanvasToToggle)` | 为某画布设置"想打开"标志，在下一个 `Update` 中处理。对有无输入绑定的画布都有效。 |
| `RequestCanvasClose(CanvasToToggle)` | 立即触发该画布的关闭事件（若它处于打开状态）+ 刷新焦点。 |
| `ReportCanvasState(CanvasToToggle, bool)` | 由面板 Manager 调用，报告自己真实的开关状态。更新 `canvasOpenOrder` 和 `isAnyCanvasOpen`。 |
| `IsCanvasFocused(CanvasToToggle)` | 返回该画布是否为当前焦点。`ICanvasManager.RefreshCanvaOrder` 用它决定 sortingOrder。 |
| `HandleFocus(CanvasToToggle)` | 拖拽式焦点切换的公开钩子。当前项目中无任何代码调用它。 |

### 2.6 已知限制（与当前代码一致）

- 按现在的代码，`UIManager` **只支持一个 ESC 键绑定**：若 `inputState[ESC]` 为 true，方法会提前 return，跳过该帧的其他绑定。当前代码不支持给 `ESC` 加第二个绑定。
- `ResetCanvas()` 由 `OnLoadScene` 调用（订阅了 `SceneLoadEventSO`）。**每次**场景切换它都会对所有 `toggleCanvasEvents` 触发 `RaiseToggleCanvasEvent(false)`。这意味着切换场景会关闭所有面板 —— 添加需要跨场景保留的面板前请先确认这是你想要的。
- `CanvasToToggle.Default` 被用作哨兵值（"无面板打开"）。不要把它用作真实面板目标 —— 代码中有多处针对 `Default` 的提前 return。

### 2.7 EventSystem（重要）

- 当前 `EventSystem` 位于 **PersistentScene**（永不卸载），保证无论在哪个内容场景下按钮都可点击。
- **不要**在内容场景（如 StartingMenu / Level01）里再放 EventSystem —— 会与 PersistentScene 的冲突，Unity 会报 "There are X event systems in the scene"。
